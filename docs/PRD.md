# PRD: Yomi — エンジニア記事を「読み切る」ための後で読むアプリ

| 項目 | 内容 |
|---|---|
| 作成日 | 2026-08-22 |
| 作成者 | Ippei |
| ステータス | Draft v0.1 |
| 対象 | iOS（iPhone）。Android / iPad は対象外 |

---

## 1. 背景・課題

X・Instagram・Web で見つけたエンジニア関連の記事を「あとで読む」つもりでブックマークし、そのまま放置してしまう。

原因を分解すると：

1. **保存先が分散している**（Xのブックマーク、Instagramの保存、Safariのリーディングリスト）ため、どこに何があるか把握できない
2. **保存した事実を忘れる**。能動的に見に行かない限り再会しない
3. **整理コストが高い**と保存すらしなくなる。逆に整理ゼロだと溜まる一方で読む気が失せる
4. 既存アプリ（Stash 等）は「整理・コレクション」が主役で、**読了に向かう導線が弱い**

## 2. 目的

「保存する場所」ではなく「消化する仕組み」を提供する。
ユーザーが保存したものを **一定期間内に読むか捨てるか判断させ、未読を溜めない** 状態を作る。

## 3. ターゲット

**一次ターゲット**：自分（Ippei）。エンジニア記事を X / Zenn / Qiita / note / Instagram 経由で日常的に保存する人。

**二次ターゲット**：同じ課題を持つエンジニア・学習者。ストア公開により獲得する。

ペルソナ：
- 通勤・昼休み・就寝前にスマホで情報収集
- X のタイムラインで記事を見かけ、ブックマークするが 8 割は読まない
- 読むタイミングは「スキマ時間に 1 本」が限界
- 凝った整理はしたくない。タグ 1 つ付けるのが限度

## 4. 成功指標

| 指標 | 定義 | 目標（自分利用） |
|---|---|---|
| 読了率 | 週の読了数 ÷ 週の保存数（週は月曜起点） | 50% 以上 |
| 未読滞留 | 未読のうち 30 日超のアイテム数 | 10 件以下 |
| 保存継続 | 週あたり保存日数 | 4 日以上 |
| Pro 転換率（公開後） | Pro 購入 ÷ 保存上限到達ユーザー | 5% |

計測は PostHog（本体アプリのみ。Share Extension では計測しない）。

## 6. 主要ユーザーストーリー

| ID | ストーリー | 受け入れ条件 |
|---|---|---|
| US-1 | X で記事を見かけたので、共有シートから 2 タップ以内で保存したい | Share Extension 起動 → 保存 → 自動で閉じる。所要 2 秒以内 |
| US-2 | 保存時に何も入力したくない | タイトル・タグは任意。空のまま保存できる |
| US-3 | 通勤中に「今日読むべき 1 本」だけ見たい | ホーム最上部に Today's Pick。タップで即閲覧 |

| US-5 | 溜まりすぎた未読を一気に整理したい | 「放置アイテム」一覧から複数選択で一括アーカイブ / 削除 |
| US-6 | 先週どれだけ読めたか知りたい | サマリ画面で保存 / 読了 / 読了率を週ごとに表示 |
| US-7 | 保存が 50 件を超えたので上限を解除したい | Paywall 表示 → 購入 → 即時解除。復元ボタンあり |

## 7. 機能詳細

### 7.1 保存（F1, F2, F12）

- 対応ソース：X、Instagram、Threads、Zenn、Qiita、note、Medium、YouTube、一般 Web。ソースは URL のホスト名で判定しアイコン表示
- Share Extension は **URL とメタ情報の受け取りのみ**行い、ネットワークアクセスは行わない（iOS の Extension メモリ制限・即時性のため）
- メタデータ取得は本体アプリ起動時およびバックグラウンドで実行
- メタ取得失敗時は URL のホスト名をタイトルにし、ユーザーが後から編集できる
- URL 正規化：`utm_*` 等のトラッキングパラメータ除去、`x.com` / `twitter.com` 統一、末尾スラッシュ統一

### 7.2 未読キュー（F3）

- 並び順：デフォルトは **保存日の古い順**（溜まっているものを先に見せる）。新しい順に切り替え可
- 各行：サムネ、タイトル、ソースアイコン、保存日、放置日数バッジ（7 日超で黄、30 日超で赤）
- スワイプ右：読んだ（read）／ スワイプ左：捨てる（archived）／ 長押し：あとで（7 日後に再通知対象）
- 無料プラン上限到達時は保存自体はできず、Share Extension 内で Paywall 誘導メッセージを表示

### 7.3 閲覧・読了（F4, F5）

- SFSafariViewController を使用（Reader モードはユーザーが Safari 側で有効化）
- 閉じた時に bottom sheet「読み終えましたか？」：`読んだ` / `まだ`
- `読んだ` → メモ入力シート（任意・1 行・後から編集可）→ read に遷移
- 読了確認は設定で OFF にできる（OFF 時はスワイプで既読化）
- 既読アイテムは「ライブラリ」タブ（既読 / アーカイブのセグメント）に移動。ホームからは消える

### 7.4 通知（F9）

- ローカル通知のみ。サーバ不要
- デフォルト 8:00。設定で変更。Pro は複数時刻設定可
- 通知内容：最古の未読 1 件のタイトル。タップで直接閲覧画面へ
- 未読 0 件のときは通知しない

### 7.5 課金（F13）

| | 無料 | Pro |
|---|---|---|
| 保存上限 | 50 件（archived 除く） | 無制限 |
| タグ | 3 個 | 無制限 |
| 通知時刻 | 1 つ | 複数 |
| メモ全文検索 | × | ○ |
| 放置自動整理 | × | ○ |
| エクスポート | ○ | ○ |
| URL 一括インポート | × | ○ |

- 商品：月額 ¥400 / 年額 ¥2,800（7 日間無料トライアル）/ 買い切り ¥5,800（non-consumable）
- RevenueCat entitlement `pro` で判定
- **開発者向けオーバーライド**：設定画面のバージョン表記 7 回タップ → アンロックコード入力。署名検証に通ると `pro` 扱い（詳細は Design Doc）
- 審査要件：サブスク説明に利用規約・プライバシーポリシーのリンク、価格・期間・自動更新の明記、「購入を復元」ボタン

### 7.6 エクスポート（F14）・インポート（F17）

- インポートは Settings → 「URL をまとめて追加」。テキストエリアに貼り付け、行・空白区切りで URL を抽出。重複は除外し件数をプレビューしてから保存。メタ取得は通常の Worker に委ねる
- 無料プラン上限（50 件）を超える分は保存しない。Pro 専用のため通常は上限なし


- JSON（全フィールド）/ CSV（title, url, source, status, tags, saved_at, read_at, memo）
- iOS 共有シートで書き出し

## 8. 非機能要件

- Share Extension の起動から閉じるまで 2 秒以内
- ホーム表示 500ms 以内（アイテム 5,000 件時）
- データは端末内のみ。外部送信は PostHog（匿名イベント）と RevenueCat（購入情報）のみ
- iOS 17 以降
- 日本語 / 英語対応（ストア説明含む）

## 9. リスク・未決事項

| リスク | 対応 |
|---|---|
| X の oEmbed 仕様変更・廃止 | フォールバックとして URL ホスト名＋保存日時をタイトルにする |
| Instagram はメタが取れない | 同上。ユーザー名のみ URL から抽出 |
| Expo で Share Extension を扱う難しさ | `expo-share-extension` を採用。Expo Go は使わず dev build 前提 |
| 端末紛失でデータ消失 | エクスポートを無料開放。v1.1 で iCloud バックアップを検討 |
| 審査リジェクト（サブスク表記） | BUZZ BASE の前例を踏襲。Paywall のテキストをリリース前にチェックリスト化 |
